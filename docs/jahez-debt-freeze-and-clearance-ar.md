# جاهز: المديونية والتجميد وتصفية الحساب

التحديث بتاريخ 11 أكتوبر 2026. اختيار نقل المديونية أو تجميد الحساب يدوي، ولا يوجد حد مالي تلقائي؛ مبلغ 15,000 ريال مثال فقط.

## السلوك

- يظهر `totalReceivable` لإجمالي الرسوم ومديونية جاهز والعمولة المرحلة وغير المرحلة. ويظهر `outstandingAmount` لإجمالي البنود الموجبة المطلوب تحصيلها؛ الرصيد الدائن في بند لا يسدد بندًا آخر تلقائيًا.
- **نقل المديونية للمندوب:** تُغلق فترة استخدامه، وتتوقف عمولته، ويصبح الحساب متاحًا لمندوب جديد بعد تسجيل مرجع تصفيته مع جاهز. يبقى دين المندوب القديم في سجله، ويصبح `accountReceivable = 0` لتلك الفترة. لا يُنشأ قبض نقدي ولا يُحذف الدين.
- **تجميد الحساب:** يصبح حساب المنصة `Suspended`، ويظل محجوزًا للمندوب الحالي. تُحسب العمولة حتى يوم التجميد بتوقيت الرياض شاملًا هذا اليوم، ولا تُحسب أيام لاحقة. تظهر المديونية على المندوب والحساب كالتزام واحد، ولا تُجمع مرتين. يُمنع إسناد الحساب أو إغلاقه أو تصفيره بالإجراءات القديمة أثناء التجميد.
- **تصفية حساب مجمد مع جاهز:** تُغلق الفترة عند وقت تنفيذ الإجراء، ويُحرر الحساب للعمل، وتبقى العمولة محدودة بتاريخ التجميد. لا يُشترط سداد المندوب؛ يبقى كامل المستحق عليه. مرجع التصفية يسجل عملية تمت خارج النظام؛ الـ API لا يتصل بجاهز ولا ينفذ تصفيرًا خارجيًا.
- **تأكيد سداد المندوب:** يجب تسجيل التحصيل أولًا عبر `/settlements`، وتكون جميع البنود المستحقة مسددة والعمولة مكتملة. يُرفض مجرد تغيير الحالة مع وجود مستحق. إذا كان الحساب مجمدًا، يُحرر بعد التأكيد. إذا أُسند الحساب لمندوب جديد، لا يتغير إسناده عند سداد المندوب السابق.

الرسوم ومديونية جاهز والعمولة مستقلة في التحصيل، مع إمكان الدفعات الجزئية. النقل والتجميد والتصفية وتأكيد الحالة لا تضيف أموالًا للخزنة. المقبوضات الفعلية فقط تدخل الخزنة بالقواعد السابقة.

يمكن تجميد الحساب حتى إن كانت تفاصيل أرباح عمولة النسبة غير مكتملة؛ تظهر `commissionComplete = false` و`problems`، وتظل العمولة محدودة بيوم التجميد. يلزم استكمال تلك التفاصيل قبل إغلاق الفترة أو تأكيد السداد، حفاظًا على مستحق المندوب الصحيح.

الحركات المتأخرة التي تقع قبل التجميد أو النقل تُنسب للمندوب السابق. لا تُقبل حركات تشغيل أثناء فترة التجميد دون إسناد صالح. ويُمنع استلام جديد بتاريخ يسبق تصفية الحساب. إذا أضيفت مديونية لاحقًا بعد تأكيد السداد، يعود `paymentStatus` إلى «مستحق»؛ `debtPaidAtUtc` يوثق التأكيد السابق فقط.

## المسارات

جميع POST تتطلب `Idempotency-Key`، وتعيد `JahezBalanceResponse` بالأسماء المرافقة للحساب والمندوب. يُرفض إعادة المفتاح مع بيانات مختلفة. الصلاحيات تُفحص ضمن نطاق منصة جاهز في الكنترولر والخدمة.

| الطريقة والمسار تحت `/api/jahez` | الغرض | الصلاحية |
|---|---|---|
| GET `/riders/{riderId}/debt-summary` | إجمالي مديونية المندوب عبر فترات حساباته، بما فيها المنقولة والمجمدة | `jahez.read` |
| POST `/handovers/{id}/transfer-debt` | نقل الالتزام للمندوب وتحرير الحساب | `jahez.resets.approve` |
| POST `/handovers/{id}/freeze` | تجميد الحساب وإيقاف العمولة | `jahez.resets.approve` |
| POST `/handovers/{id}/clear-account` | تأكيد تصفية الحساب المجمد مع جاهز وتحريره | `jahez.resets.approve` |
| POST `/handovers/{id}/confirm-paid` | تأكيد سداد دين فترة مغلقة أو مجمدة | `jahez.collections.create` |

`id` هو معرف فترة التسليم `handoverId`، وليس معرف حساب المنصة. هذه الإجراءات المباشرة متاحة لمن يملك صلاحية اعتماد التصفير؛ مسار طلبات التصفير السابق يحتفظ بقاعدة الاعتماد من مستخدم آخر.

النقل:

```json
{
  "effectiveAtUtc": "2026-10-11T12:00:00+03:00",
  "reason": "المندوب غادر ونُقلت المديونية للمتابعة",
  "externalClearanceReference": "JAHEZ-RESET-123"
}
```

التجميد:

```json
{
  "effectiveAtUtc": "2026-10-11T12:00:00+03:00",
  "reason": "المندوب هرب والحساب لم تتم تصفيته"
}
```

تصفية الحساب المجمد (وقت التنفيذ هو وقت التحرير؛ لا يُعاد تأريخه):

```json
{
  "reason": "تمت تصفية الحساب مع جاهز وتبقى مديونية المندوب",
  "externalClearanceReference": "JAHEZ-CLEAR-456"
}
```

تأكيد السداد بعد تسجيل القبض عبر `/settlements`:

```json
{ "reason": "تم سداد جميع مستحقات المندوب" }
```

## حقول العرض

`debtStatus` في كشوف الأرصدة والتسليمات:

| القيمة | الحالة |
|---|---|
| 1 | استخدام نشط |
| 2 | فترة مغلقة بالإجراء السابق |
| 3 | المديونية منقولة للمندوب |
| 4 | حساب مجمد |
| 5 | الحساب المجمد تمت تصفيته وتحريره |

`paymentStatus` منفصل: 1 مستحق، 2 مسدد. تصفية الحساب لا تعني سداد المندوب.

حقول الرصيد الإضافية: `outstandingAmount`, `accountReceivable`, `isAccountFrozen`, `isAccountReady`, `frozenAtUtc`, `accountClearedAtUtc`, `debtPaidAtUtc`. قيمة `isAccountReady` تعكس جاهزية الحساب الحالية، وتصبح false إذا استلمه مندوب جديد. يحتفظ سجل التسليم أيضًا بـ `externalClearanceReference`.

ملخص المندوب يعيد `riderProfileId`, `totalReceivable`, `outstandingAmount`, `fees`, `platformDebt`, `commission`, `frozenAccountCount`, `paymentStatus`، وأسماء المندوب. استخدمه لبطاقة إجمالي المديونية بدل جمع صفحة واحدة من `/debts`. استخدم كشوف الأرصدة لعرض تفاصيل الفترات ومشكلات اكتمال العمولة.

كل تغيير جديد يسجل قيدًا غير مالي بمبلغ صفر في الدفتر، `kind = 6`، مع السبب والمستخدم و`calculationJson` الذي يحتوي الإجراء والحالة السابقة والجديدة ووقت السريان ومرجع التصفية. تُحفظ الأرصدة والقيود السابقة.

## مثال

مديونية جاهز 15,000 ريال + رسوم غير مدفوعة 200 + عمولة 75 = مستحق 15,275 ريال. عند التجميد يظل الإجمالي ثابتًا في الأيام اللاحقة. بعد تصفية الحساب خارجيًا، يصبح مستحق الحساب لتلك الفترة صفرًا، ويبقى 15,275 ريال على المندوب. المندوب الجديد يبدأ فترة مستقلة برسومه وعمولته دون مديونية المستخدم السابق.

## قاعدة البيانات والنشر

المهاجرة `AddJahezDebtFreezeAndClearance` تضيف حقول الحالة والتوقيت والمرجع، مع قيود تحقق. تُهيئ السجلات القديمة: المنقولة إلى الحالة 3، والمغلقة إلى 2، وباقي السجلات إلى 1. لا تغير المبالغ ولا تُحوّل حسابات قديمة إلى مجمدة تلقائيًا.

سكريبت النشر المستقل: `database/scripts/jahez-debt-freeze-and-clearance.sql`. طُبق الترحيل على قاعدة البيانات المستضافة `db67927` يوم 11 أكتوبر 2026 الساعة 16:12 بتوقيت الرياض، مع التحقق من الحقول والقيود وسجل الترحيل والحفاظ على البيانات المالية. راجع [تقرير التطبيق والتحقق](jahez-debt-migration-deployment-20261011.md). نشر نسخة API المحدثة إجراء مستقل لم يُنفذ ضمن تحديث قاعدة البيانات. لا ترجع إلى النسخة السابقة أثناء وجود حسابات مجمدة؛ النسخة السابقة لا تعرف تاريخ إيقاف عمولتها.

## التحقق

نجحت 45 حالة اختبار في مشروع جاهز، بما فيها النقل والتجميد وثبات العمولة والتصفية الخارجية والسداد ومنع تجاوز التجميد من واجهتي حسابات المنصات، وكذلك توليد مخطط SQL وترجمة الاستعلامات. تحقق EF من تطابق الموديل مع آخر مهاجرة. تعذرت 4 حالات تتطلب LocalDB لأن تشغيله يفشل على الجهاز. لاحقًا طُبق ترحيل المخطط بنجاح داخل معاملة على قاعدة البيانات المستضافة؛ لم تُشغل اختبارات الأعمال التي تكتب بيانات اختبار على قاعدة التشغيل.
