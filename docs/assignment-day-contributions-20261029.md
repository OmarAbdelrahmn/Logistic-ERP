# التسليم وفصل اليوم والاستخدام الشهري — 29 أكتوبر 2026

## الواجهة

احذف حقول فصل اليوم من نموذج استلام الحساب من المندوب. طلبات الاستلام القديمة التي ترسل `dayUsage` ما زالت مدعومة، ولا يوجد إلزام بإرسالها.

عند فتح التسليم أو تغيير الحساب أو تاريخ التسليم أو المندوب، اقرأ:

`GET /api/platform-accounts/{id}/assignment-context?date=2026-10-29&riderProfileId=GUID`

يعيد `contributions` بالترتيب، وأسماء المندوبين، ومعرّفات العهدات، والأرقام الحالية، والحقول الناقصة ورموز التزامن. القراءة لا تحفظ أي سجل. استعمل `requiresPreviousUsage` لإظهار ضرورة استكمال الطلبات. اعرض ساعات ومبالغ نينجا وعروض شيفز كحقول اختيارية. أسماء الحقول في قوائم النواقص هي PascalCase مثل `OrdersCount`، وخصائص JSON هي camelCase.

احتفظ بالبيانات الموجودة. أرسل فقط المساهمات التي تستكملها، داخل طلب التسليم نفسه؛ لا تنفذ PUT مستقلًا قبل التسليم. لكل مساهمة مرسلة، أرسل كائن الأرقام كاملًا مع رموز التزامن كما عادت من السياق:

```json
{
  "previousDayUsages": [
    {
      "assignmentIds": ["PREVIOUS_ASSIGNMENT_GUID"],
      "figures": { "ordersCount": 0 },
      "rowVersion": "TOKEN_FROM_CONTEXT",
      "usageRowVersions": { "PREVIOUS_ASSIGNMENT_GUID": "USAGE_TOKEN_FROM_CONTEXT" }
    }
  ]
}
```

هذه إضافة إلى باقي بيانات طلب التسليم المعتادة. يتوفر الحقل في التسليم العام، ومسار الإسناد القديم، ونينجا وجاهز. اعتماد FreeSwitch في جاهز يقبل الحقل نفسه في طلب القرار، ويعيد التحقق عند إنشاء العهدة المستهدفة داخل المعاملة الحالية.

الصفر مؤكد؛ null غير معروف. عدد الطلبات فقط مطلوب قبل الانتقال إلى مندوب آخر في نفس اليوم. لا تفرض حقول الساعات أو المبالغ أو العروض؛ الاستيراد الذي يحتاجها سيبقى متوقفًا حتى استكمالها. عند 409 أعد تحميل السياق. العضوية والترتيب والأرقام المحفوظة يعاد التحقق منها على الخادم تحت قفل الحساب؛ لا يمكن تغيير أرقام سابقة عبر التسليم.

## نفس المندوب والتصحيح

`A → A` لا يطلب فصلًا. `A → A → B` يطلب إجمالي A عبر الفترتين. `A → B → A` يبقى ثلاث مساهمات. تجميع نفس المندوب متتالٍ فقط؛ يستمر منع مشاركة شيفز FullTime.

سجل العهدات لا يُدمج أو يُحذف. تحفظ المجموعة عضويتها وأرقامها وسببها ورمز التزامن بشكل مستقل. الاستيراد ينسب حصة المجموعة لآخر عهدة، والمجموعة تحتفظ بدليل العهدات المغطاة. الأيام القديمة التي لم ينشأ لها سجل مجموعة تحتفظ بمنطقها السابق. المجموعات المعتمدة لا يعاد تشكيلها؛ قواعد منع إدخال عهدة على يوم تم استيراده ما زالت مطبقة.

`GET day-usage` يعرض `assignments` القديمة إضافة إلى `contributions`. لتصحيح مجموعة غير معتمدة أرسل `PUT day-usage?date=...` مع كل العهدات بترتيبها كالمعتاد، و`figures: null` للمحافظة عليها، وقائمة `contributions` بنفس شكل `previousDayUsages` وسبب التصحيح. لا تعدل أرقام العهدات الفردية المغطاة بمجموعة؛ عدل مساهمتها المجمعة. الحقول المعتمدة تحتاج مسار تصحيح الاستيراد الحالي. معاملات جاهز ذات الطابع الزمني تبقى مرتبطة بجلساتها الفعلية.

## الاستخدام الشهري

تمثيلات حسابات المنصات العامة، ونينجا وشيفز وجاهز والحسابات المتداخلة في المقارنات والتفاصيل تُرجع:

```json
{ "monthlyUsageStatus": "Used", "usageMonth": "2026-10" }
```

القراءة تجمع الحسابات الظاهرة في الرد وتستعلم عن استخدامها دفعة واحدة، وتستخدم الوقت الحالي من TimeProvider بتوقيت الرياض. عهدة فعلية غير محذوفة أو ملغاة تتداخل مع الشهر حتى الآن تعني Used. العهدات المخططة والمستقبلية مستبعدة. الحساب الراجع خلال الشهر يظل Used، والحساب المستمر مع مندوب من الشهر السابق يظل Used في بداية الشهر الجديد. الحساب الذي لم يستخدم خلال الشهر يصبح Unused تلقائيًا. جلسة جاهز المنتهية عند منتصف الليل أول الشهر لا تُحسب للشهر الجديد. لا توجد مهمة reset، ولا يتغير status التشغيلي.

## الإصدار والتحقق

طبّق Migration `MoveDayContributionsToAssignment` قبل نشر API مطابق. تضيف جدول `app.PlatformAccountDayContributions` فقط، بدون تعديل أرقام التاريخ القديم. الرجوع إلى إصدار قديم بعد تشغيل الميزة غير آمن؛ Down يرفض حذف جدول يحتوي على دليل مجموعات. جهز نسخة احتياطية واستخدم التصحيح إلى الأمام.

نسّق نشر الفرونت مع API؛ العميل القديم قد يتلقى 409 عند التسليم لنفس يوم مندوب سابق إذا لم يستكمل عدد طلباته. لا يُنشر مشروع فرونت من هذا المستودع.

التحقق الآلي يغطي الفصل والصفـر والحقول الاختيارية وتجميع نفس المندوب وحدود الشهر والردود المتداخلة. اختبارات SQL التزامن تتطلب `NINJA_SQL_TEST_SERVER` وتشغّل قاعدة مؤقتة منفصلة؛ لا توجّهها إلى قاعدة التشغيل.
