## API

`GET /api/housing/{id}` returns `rooms` and `floors`. Each room has `floorId`, `notes`, `equipment`, `occupants`, `externalOccupants`, and `pendingOccupants`. Each floor has its own `equipment`, its `rooms`, capacity and occupancy totals, and read-only `totalEquipment` summed by item name across the floor and rooms. `GET /api/housing/{id}/floors` returns the same floor detail independently.

Housing and room CRUD continue through the existing endpoints. Room create and update accept optional `floorId` and `notes`; omitted `floorId` on create selects the first floor. Room numbers are unique within a floor.

- `POST /api/housing/{id}/floors`, `PUT /api/housing/{id}/floors/{floorId}`, `DELETE /api/housing/floors/{floorId}` manage floors. A floor with rooms or equipment cannot be deleted.
- `POST /api/housing/floors/{floorId}/equipment`, `PUT /api/housing/floors/{floorId}/equipment/{equipmentId}`, and `DELETE /api/housing/equipment/{equipmentId}` manage floor equipment.
- `POST /api/rooms/{id}/equipment` and `PUT /api/rooms/{id}/equipment/{equipmentId}` manage room equipment. The same delete endpoint removes either equipment scope.
- `POST /api/rooms/{id}/occupants/external`, `PUT /api/rooms/occupants/external/{occupantId}`, and `DELETE /api/rooms/occupants/external/{occupantId}` manage name-only occupants. A PUT may move the person using `roomId`; capacity is checked.
- `POST /api/rooms/{id}/occupants/iqama` assigns an existing employee by iqama. If that room has a matching pending occupant, the pending row is resolved without increasing occupancy twice.
- `POST /api/rooms/occupants/pending/{pendingId}/resolve` links a pending occupant once the employee has been created; body: `{ "effectiveFrom": "2026-09-29" }`. `DELETE /api/rooms/occupants/pending/{pendingId}` removes an incorrect pending row and reduces occupancy.

Housing read permission protects read endpoints. Housing manage permission protects all mutations. Floor and equipment responses include row versions for updates. The aggregate `totalEquipment` rows have no editable identity.

This repository contains the backend API and frontend handoff, but no source for the linked Hostinger admin page. The new controls become available to that page after the updated API is deployed and its frontend is changed to call these routes.
