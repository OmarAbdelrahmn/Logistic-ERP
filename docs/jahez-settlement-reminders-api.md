# Jahez settlement reminders

`GET /api/jahez/v2/settlement-reminders?page=1&pageSize=50` returns `{ items, page, pageSize }`. Each item contains `handoverId`, `accountId`, `externalAccountId`, `riderProfileId`, `riderName`, `reminderAnchorAtUtc`, `daysSinceSettlement`, and `administrativeDebt`. Requires `jahez.read` scoped to Jahez. Page size is 1–100.

`administrativeDebt` is the account's current administrative debt (المديونية الإدارية), using the same signed balance as `platformDebt` in the administrative-debts endpoint. It sums platform-debt ledger entries across the account, including legacy entries linked through handovers. It is `0` when no debt exists and may be negative for a credit. Each assigned account shows its current account balance, including debt from earlier sessions; this is not a historical balance at the settlement date.

The list is calculated on request and includes only currently assigned accounts with an open session that has started, regardless of elapsed days, settlement completion, or unpaid transferred debt. Ended and future sessions are excluded before pagination. It returns one row per handover session, not one row per settlement operation. `reminderAnchorAtUtc` is the last executed settlement time, or handover start if none; `daysSinceSettlement` counts Riyadh calendar days from that anchor. For example, a session settled 3 days ago is included with `daysSinceSettlement: 3`. Results remain paginated and ordered by handover ID. The worker no longer generates Jahez overdue notifications. Existing notifications are not deleted.

Order inactivity is included in the same rows: `isAssigned`, `lastOrderDate`, `daysWithoutOrders`, and `noOrdersForThreeDays`. Every returned session is currently open and has started, so `isAssigned` is true. For an assigned session, the last date with a positive order count comes from committed dispatch imports, excluding batches replaced by a committed correction. The day count uses Riyadh calendar dates from the later of that date and the session start. If no positive order is recorded for the session, `lastOrderDate` is null and the count starts at assignment; the flag becomes true at three days. A null last order date means no positive order was found in the imported data, not proof that imports cover every day. The flag clears when a newer positive order is imported. Pagination applies to the assigned sessions.
