# وحدة جاهز: التشغيل وواجهات Backend

تنفيذ Backend فقط. تستخدم الوحدة منصة `ClientPlatform.Code = JAHEZ`، وحسابات المنصات والمندوبين والإسنادات الحالية. لا يوجد اتصال مباشر بمنصة جاهز، ولا تعديل للملفات الأصلية، ولا واجهة مستخدم ضمن هذا التغيير.

## الحساب والمندوب والكفلاء

`RegisteredEmployeeId`/`OwnerRiderProfileId` هو صاحب الحساب الرسمي. `RiderProfileId` في استلام جاهز هو المستخدم الفعلي الذي يتحمل الحركات والعمولة والطلبات خلال فترة استخدامه. لا تُنسب الطلبات إلى المالك لمجرد أن الحساب باسمه.

`DashboardSponsorId` علاقة مستقلة بقائمة `Sponsors`، أضيفت لكل حسابات المنصات وطلبات الإنشاء والتعديل والاستجابات والتصفية والتصدير CSV. لا تنسخ قيمة كفيل الموظف أو `SponsorId` تلقائيًا. الحقل إلزامي عند إنشاء حساب جديد في الواجهات الأساسية والتوافق، والحسابات القديمة يمكن استكماله عند تعديلها؛ لا يمكن مسح القيمة بعد استكمالها. استلام حساب جاهز جديد يتطلب وجوده. مرشح قوائم الحسابات: `dashboardSponsorId`.

أنشئ الحساب من API حسابات المنصات، ثم استلمه من `/api/jahez/handovers`. الإسناد والإغلاق العام لحساب جاهز يعيدان خطأ يطلب استخدام وحدة جاهز، لمنع تجاوز الرسوم والعمولة. الحساب المدعوم `PayPerOrder`، والمندوب نشط. يسمح مسار جاهز بحسابين نشطين للمندوب ضمن خانتي الإسناد الموجودتين؛ قواعد المنصات الأخرى الحالية لم تتغير. لا يمكن تغيير رقم الحساب الخارجي أو منصته بعد إنشاء تاريخ مالي لجاهز.

## conventions والنتائج

- المسار الأساسي `/api/jahez`؛ المصادقة ونموذج ProblemDetails مطابقان لبقية النظام. النجاح يعيد الجسم مباشرة مع HTTP 200.
- جميع أوامر POST تتطلب رأس `Idempotency-Key` غير فارغ، بحد 150 حرفًا. احتفظ به عند إعادة محاولة الطلب نفسه. نفس المستخدم والعملية والمفتاح والبيانات يعيدون نتيجة الأمر الأصلية، بينما تغيير البيانات بالمفتاح نفسه يعيد 409. إعادة المحاولة تخضع للصلاحية الحالية أيضًا.
- `DateOnly` بصيغة `yyyy-MM-dd`، واللحظات الزمنية ISO 8601 مع المنطقة الزمنية؛ تحفظ UTC. الأيام والعمولة والتذكيرات وفق الرياض UTC+3. إرسال توقيت الرياض بـ`+03:00` مقبول.
- JSON يستخدم camelCase، وenums التالية أرقام. لا ترسل أسماء enums النصية في JSON. `kind` في multipart يمكن إرساله كرقم.
- القوائم تعيد `{ items, page, pageSize }`؛ الافتراضي صفحة 1 وحجم 50، الحد 100. لا يوجد total count في العقد.
- السبب مطلوب لأوامر التغيير، حد 2000 حرف. مبالغ القبض موجبة، بدقة هللتين؛ القيم المصدرية والدفتر المالي محفوظة بدقة ست منازل عشرية. حد القيمة المدخلة مليار ريال.
- 400 للبيانات غير الصالحة، 403 للصلاحية، 404 للسجل/المنصة، 409 للتعارض أو الفترة المقفلة أو الاعتماد الذاتي. مشاكل صفوف الاستيراد تعاد في المعاينة وتمنع الترحيل.

| النوع | القيم الرقمية |
|---|---|
| نوع طلب الموافقة | 1 إعفاء رسوم، 2 تبديل مجاني، 3 عمولة نسبة، 4 تصفير ونقل دين |
| حالة الطلب | 1 معلق، 2 معتمد، 3 مرفوض، 4 ملغى |
| بند الدفتر `bucket` | 1 رسوم حساب، 2 دين جاهز، 3 عمولة |
| نوع القيد | 1 استحقاق، 2 سداد، 3 تسوية، 4 نقل مسؤولية، 5 افتتاحي |
| قسم الصندوق | 1 رسوم، 2 تصفيات |
| حالة تسليم الصندوق | 1 معلق، 2 أكد المحاسب، 3 معتمد، 4 مرفوض |
| نوع الاستيراد | 1 حركات، 2 طلبات يومية |

## استلام وتصفية جزئية

مثال استلام؛ استبدل المعرفات بمعرفات موجودة:

```json
{
  "accountId": "11111111-1111-1111-1111-111111111111",
  "riderProfileId": "22222222-2222-2222-2222-222222222222",
  "effectiveAtUtc": "2026-10-01T08:00:00+03:00",
  "reason": "تسليم حساب جاهز",
  "initialFeePayment": 80
}
```

تحفظ الاستجابة `id` وهو `handoverId` المستخدم في العمليات المالية. الرسوم المتبقية 120، المقبوض 80 يدخل قسم الرسوم. لا تعتبر الدفعة الأولى تصفية، ولا تسجل الأرصدة غير المقبوضة في الصندوق. `feeApprovalRequestId` يُترك فارغًا؛ الإعفاء عبر الطلبات أو التبديل المجاني المعتمد.

العمولة من 2 إلى 6 أكتوبر = 75. يوم الاستلام معفى، ويوم الإغلاق محسوب إذا كان بعد يوم الاستلام. الاستحقاق مستمر رغم غياب الطلبات، ولكل حساب مستقلًا. التصفية تثبت الأيام حتى `throughDate` ولا توقف الاستخدام أو تعيد تحميل الأيام السابقة.

```json
{
  "handoverId": "33333333-3333-3333-3333-333333333333",
  "throughDate": "2026-10-06",
  "feePayment": 50,
  "debtPayment": 100,
  "commissionPayment": 75,
  "countsAsSettlement": true,
  "reason": "دفعة تصفية جزئية"
}
```

توزع الدفعة صراحة: 50 قسم رسوم و175 قسم تصفيات. لا يمكن تجاوز المستحق لكل بند أو إرسال دفعة إجمالية صفر. `countsAsSettlement: true` يعيد عد التذكير عند قبض فعلي ولو جزئيًا. لتسجيل رسوم فقط خارج التصفية، استخدم false و`debtPayment = commissionPayment = 0`؛ لا تتغير نقطة التذكير.

المعاينة تعرض `fees`, `platformDebt`, `postedCommission`, `unpostedCommission`, `totalReceivable`, `commissionComplete`, `problems`, `reminderAnchorAtUtc`, `daysSinceSettlementPayment`, `isOverdue`, `latestTransactionAtUtc`. هذه معاينة للمستحق الحالي مع حد الحركات `through`، ولا تستخدم ككشف تاريخي بعد دفعات لاحقة. لا يجوز اختيار تاريخ أسبق من العمولة المثبتة أو آخر فترة تصفية؛ التقارير التاريخية من الدفتر والدفعات. المديونية غير المسددة من الفترات المغلقة تبقى في الفترة القديمة، ويمكن سدادها دون تكرار أصلها.

`Net Amount` السالب يحمل دينًا موجبًا بالقيد `-NetAmount`. الموجب رصيد دائن يظهر في الكشف ولا ينشئ صرفًا نقديًا. الدفعات قيود سالبة تقلل المستحق، والتسويات الموثقة قد تكون موجبة أو سالبة. التحصيل والصندوق ينشآن فقط من القبض الفعلي.

## الطلبات والموافقات

```json
{
  "handoverId": "33333333-3333-3333-3333-333333333333",
  "kind": 2,
  "targetAccountId": "44444444-4444-4444-4444-444444444444",
  "effectiveAtUtc": "2026-10-04T12:00:00+03:00",
  "reason": "ضعف وصول الطلبات للحساب القديم"
}
```

يرسل مستخدم آخر القرار `{ "approve": true, "reason": "تم التحقق والاعتماد" }`. تصل نتيجة الاعتماد/الرفض إلى مقدم الطلب في الإشعارات الحالية. إلغاء المعلق: `{ "reason": "لم يعد الاستثناء مطلوبًا" }` بواسطة مقدمه.

- إعفاء الرسوم kind=1: `waiverAmount` موجب لا يزيد عن غير المدفوع، ولا يرد مبلغًا سبق قبضه.
- تبديل مجاني kind=2: الحساب الجديد متاح، ويغلق القديم عند اللحظة المحددة وينشئ الجديد للمندوب نفسه بإعفاء 200. المتبقي القديم والعمولات والديون يبقون عليه. إذا تغير توافر الحساب قبل الاعتماد يرفض الأمر كاملًا.
- نسبة kind=3: `fromDate` و`toDate` إلزاميان. النسبة ثابتة 15%، لا تتداخل الفترات المعتمدة ولا تشمل أيامًا مثبتة في تصفية. بعد نهايتها يعود 15 ريالًا يوميًا.
- تصفير kind=4: `effectiveAtUtc` وسبب، و`externalResetReference` اختياري. الاعتماد يغلق الإسناد ويثبت العمولة ويعلم الدين بأنه منتقل إلى متابعة المندوب السابق، ويتيح الحساب لمندوب جديد. لا يضاعف أصل الدين ولا يقبض مالًا. الحركة المتأخرة بحسب وقتها ترتبط بالمستخدم القديم. المرجع الخارجي يوثق إجراء داشبورد يدويًا.

الإغلاق العادي يستخدم `{ "effectiveAtUtc": "...", "reason": "..." }` ويبقي المستحق في كشف المستخدم. لا يسمح بالإغلاق قبل حركات مرحلة لاحقة أو أيام عمولة مثبتة. الحسابات القديمة تهيأ عبر `legacy-adoptions`: `assignmentId`, `financialStartOn`, `openingDebt`, `openingFees`, `openingCommission`, `reason`. لا تنشأ رسوم 200 أو عمولات تاريخية آليًا؛ يوم البداية المالية الصريح يبدأ الاحتساب للحساب القديم. الدين الافتتاحي يمكن أن يكون دائنًا بالسالب. يجب تجنب استيراد حركات سبق تضمينها في الرصيد الافتتاحي؛ ذلك مسؤولية اختيار نقطة البدء في التهيئة.

## أرباح النسبة

```json
{
  "handoverId": "33333333-3333-3333-3333-333333333333",
  "fromDate": "2026-10-02",
  "toDate": "2026-10-06",
  "totalDeliveryPrice": 1000,
  "totalPenalties": 20,
  "totalCashAmount": 100,
  "totalDriverDebit": 10,
  "totalServiceDeduction": 5,
  "totalDriverCredit": 50,
  "totalBonuses": 30,
  "totalTips": 10,
  "totalFreeOrders": 5,
  "reason": "إدخال كشف الفترة"
}
```

أساس العمولة = التوصيل − الغرامات − النقد − debit − خصم الخدمة + credit + المكافآت + الإكراميات + قيمة الطلبات المجانية. المثال أساسه 960 وعمولته 144. كل بند مطلوب صراحة ولو صفرًا، وقيم البنود غير سالبة. `totalFreeOrders` مبلغ، والعدد يأتي من ملف الطلبات. أساس صفر/سالب ينتج عمولة صفر.

تغطي البيانات اليدوية أيام فترة النسبة التي تدخل في التصفية دون فجوات أو تداخل. يمكن تقسيم السياسة إلى كشوف متتابعة والتصفية لكل جزء؛ لا تقسم قيمة كشف يدوي نسبيًا على أيامه، لذا تاريخ القطع يجب أن يوافق نهاية كشف مكتمل. عدم اكتمالها يظهر في المعاينة ويمنع تثبيت التصفية/الإغلاق. لا تجمع العمولة اليومية والنسبة في الأيام نفسها. تصحيح كشف غير مثبت يكون بإرسال `supersedesId` مع نفس الفترة والسبب، مع حفظ النسخة السابقة؛ لا تعدل البيانات المثبتة.

قيود العمولة تحفظ نطاق الأيام و`calculationJson` متضمنًا الشرائح اليومية ومراجع السياسة والموافقة وكشوف الأرباح وأساس الحساب؛ مصدر قيد العمولة هو معرف القيد نفسه. لا يسمح بحذف السجلات المالية التاريخية أو تعديلها مباشرة.

## استيراد الملفات

POST `/imports` هو multipart: `kind`, عدة `files`, و`replacesBatchId`, `correctionReason` عند التصحيح. الحد 10 ملفات، 10MB لكل ملف، 30MB إجماليًا، و50000 صف للدفعة. يقبل XLSX بقيم أصلية، ويرفض صيغ Excel في الأعمدة المطلوبة. محتوى الخلايا بيانات مصدرية ولا ينفذ كتعليمات.

| kind | الورقة | الأعمدة المطلوبة |
|---|---|---|
| 1 | SDP_Report | Driver ID, Date, Delivery Price, Cash Amount, Net Amount, Driver Adjustment |
| 2 | Delivery Insights Report | Driver ID, From, To, Number Of Dispatches |

تختلف مواضع الأعمدة مسموحًا، وعناوينها المطلوبة يجب أن تكون موجودة. التاريخ الفعلي أساس الإسناد، لا اسم الملف. يحفظ الأصل والصف و`rawValuesJson` والقيم المالية دون تقريب المصدر. نتيجة الرفع تحفظ دفعة معاينة مع `batchId`, `rows`, `issues`, `files` (معرفات التنزيل). الربط `Driver ID` إلى `ExternalAccountId` في جاهز ثم فترة المستخدم وقت الحركة. الحساب غير المعروف أو غياب الإسناد أو التاريخ المستقبلي أو القيمة غير الصالحة يمنع الترحيل حتى تُحل المشكلة ويعاد طلب المعاينة.

المعاينة تتضمن `accounts` لملخص كل رقم حساب: حدود الفترة الفعلية، `validRowCount` للصفوف المقروءة، `netAmount` بدقة المصدر، `platformDebtChange = -netAmount` للحركات، وإجمالي `dispatches` للطلبات، وعلامة `hasIssues`. الملخص يوضح أثر الملف المقترح ولا يمثل مبلغًا مقبوضًا أو الرصيد الحالي بعد الدفعات؛ الرصيد الحالي من مسار balance. الصفوف ذات خطأ القراءة موجودة في issues ولا تدخل في المجاميع.

ترحيل الحركات POST `/imports/{id}/commit` بجسم `{}`. لا ينشأ قبض أو صندوق من الاستيراد. تحميل الملف ذاته أو دفعة الملفات ذاتها لا يكرر الترحيل حتى بمفتاح مختلف. لا تحذف صفوفًا متطابقة تلقائيًا لأنها قد تكون حركات صحيحة مختلفة. التداخل مع دفعة حركات نشطة للحساب بين أول وآخر توقيت لها يمنع الترحيل. لا توجد تسوية صامتة للتداخل.

الطلبات اليومية تتطلب From=To. التقرير متعدد الأيام لا يوزع تلقائيًا. إذا تغير المستخدم أثناء اليوم، تحتوي المعاينة `assignment_ambiguous`، ويرسل التوزيع اليدوي للترحيل:

```json
{
  "allocations": [
    { "rowId": "55555555-5555-5555-5555-555555555555", "handoverId": "33333333-3333-3333-3333-333333333333", "count": 10, "reason": "طلبات قبل التبديل" },
    { "rowId": "55555555-5555-5555-5555-555555555555", "handoverId": "66666666-6666-6666-6666-666666666666", "count": 4, "reason": "طلبات بعد التبديل" }
  ]
}
```

المجموع يجب أن يساوي عدد الصف، والفترات من مستخدمي الحساب لذلك اليوم، والأسباب موثقة. لا يسمح بتقريرين نشطين للحساب واليوم نفسه. الطلبات لا تعدل العمولة اليومية أو الأرقام المالية.

لتصحيح دفعة مرحلة، ارفع النسخة البديلة بـ`replacesBatchId` وسبب. الاستبدال كامل للدفعة، بنفس الحسابات وحدود الأيام، ويعكس قيود الدين القديمة ويضيف الجديدة ذريًا، مع حفظ الملفات والصفوف القديمة ومراجع العكس. لا يستبدل جزءًا من الدفعة ولا يعيد استعمال دفعة استبدلت سابقًا. تقرير الطلبات يستبعد النسخة المستبدلة. إدخال مبلغ مصحح لا يعكس قبضًا سابقًا أو تسليم صندوق.

اختبار الملفات المرفقة تحقق من 485 حركة بإجمالي `Net Amount = -10188.144` ومن 114 صف طلبات بإجمالي 1106. حركة 1 أكتوبر موجودة بالفعل داخل ملف اسمه سبتمبر، وتفسر بتوقيتها الفعلي بالرياض.

## الصندوق والتسليم

GET `/cashbox` يعيد إجمالي غير المسلّم في `fees` و`settlements`، والمحجوز في `reservedFees` و`reservedSettlements`، والمتاح في `availableFees` و`availableSettlements`.

1. POST `/cashbox/handovers`: `{ "businessDate": "2026-10-06", "reason": "تسليم اليومية" }` يحجز جميع المقبوضات المتاحة حتى نهاية ذلك اليوم، ويثبت `feeAmount` و`settlementAmount`.
2. مستخدم محاسب آخر يؤكد `{ "feeAmount": 130, "settlementAmount": 175, "reason": "استلام ومطابقة القسمين" }`؛ يجب التطابق في كل قسم مستقلًا.
3. مستخدم ثالث يرسل قرار الموافقة أو الرفض. الاعتماد يخرج المبالغ من العهدة المتاحة ويبقي الربط والتاريخ؛ الرفض يحرر الحجوزات للتسليم التالي.

المقبوضات الجديدة بعد إنشاء الطلب لا تدخل فيه. لا تحجز الحركة في طلبين. مجموع القسمين المتطابق مع توزيع خاطئ غير مقبول. تحفظ أسباب الإنشاء والتأكيد والقرار منفصلة. هذا التسليم لا يغير دين المندوب أو عد التذكير.

## التذكير والمهام الخلفية

`JahezReminderWorker` مسجل في Worker، يعمل عند التشغيل ثم كل ساعة. يبدأ العد من الاستلام، أو آخر دفعة تصفية فعلية. يتأخر الحساب عند مرور أكثر من 10 أيام تقويمية بالرياض. لا يعيد العد رفع ملف أو إنشاء طلب أو تصفير أو دفع رسوم منفرد. يستمر الدين القديم بعد التصفير في المتابعة.

ينشأ إشعار داخلي للمستخدمين النشطين أصحاب `jahez.read` في نطاق جاهز، مع حالة تمنع التكرار للحلقة نفسها. دفع فعلي/انتهاء الدين يحل الحالة ويغلق إشعارها؛ التأخر بعد دفعة جديدة ينشئ حلقة جديدة. شغل Worker مع قواعد الاتصال والإشعارات المعتادة؛ لا توجد أتمتة Codex أو رسائل خارج النظام.

## قاعدة البيانات والتحقق والنشر

الكيانات في Domain، والعقود في Application، والخدمات وEF في Infrastructure، وController في Api. الجداول الجديدة في schema `jahez`، وتتضمن الاستلام والرسوم والموافقات والسياسات والأرباح والاستيراد والحركات والطلبات والتصفية والدفتر والصندوق والتذكير وإيصالات عدم التكرار. تستخدم العمليات المالية SQL transaction بعزل Serializable واستراتيجية إعادة المحاولة، وقيود uniqueness ومراجع restrict؛ النسخ التاريخية append-only وفق interceptor النظام الحالي. المعاينة لا تكتب قبضًا.

ترحيلات Application:

- `20261003151506_AddJahezOperations`.
- `20261003153822_PreserveJahezFinancialEvidence`.

ترحيل Identity: `20261003152452_GrantJahezPermissions`.

السكريبتان [Application](sql/jahez-application.sql) و[Identity](sql/jahez-identity.sql) idempotent ويغطيان إضافات جاهز بعد ترحيلات فصل صلاحيات المناديب/أوامر العمل الموجودة. يجب تطبيق الترحيلات السابقة أولًا. **طُبقت ترحيلات جاهز الثلاثة على قاعدة التطبيق `db67927` في 3 أكتوبر 2026**. تحققنا من 17 جدولًا في schema `jahez`، وحقل `DashboardSponsorId`، و13 تعريف صلاحية و13 منحة `SYSTEM_ADMIN`، ومن عدم وجود ترحيلات معلقة أو اختلاف بين النموذج والترحيلات في سياقي Application وIdentity. أوامر تطبيق الترحيلات على بيئة أخرى:

```powershell
dotnet ef database update --project src/LogisticsERP.Infrastructure --startup-project src/LogisticsERP.Api --context ApplicationDbContext
dotnet ef database update --project src/LogisticsERP.Infrastructure --startup-project src/LogisticsERP.Api --context IdentityDbContext
```

شغل الاختبارات:

```powershell
dotnet test tests/LogisticsERP.Jahez.Tests/LogisticsERP.Jahez.Tests.csproj
# يتطلب LocalDB صالحًا؛ ينشئ قاعدة LogisticsJahezTest_<guid> مؤقتة ويزيلها فقط.
```

نجحت 27 حالة اختبار لجاهز، تشمل الملفات الأصلية والقبض الجزئي والرصيد الدائن وتوزيع الطلبات التاريخي واستقلال كفيل الداشبورد والتذكير والصلاحيات بنطاق المنصة. اختبارات الأعمال تعمل على InMemory مع interceptor الحقيقي؛ اختبار نموذج SQL وتوليد DDL وترجمة استعلامات SQL يعمل دون اتصال.

يوجد اختبارا تكامل اختياريان على LocalDB: سير العمل المالي الكامل، والتحصيل المتزامن مع التراجع عند فشل تبديل إلى حساب مستخدم. تعذر تشغيل التكامل على هذا الجهاز بسبب فشل بدء SQL Server، لذا لا تثبت اختبارات InMemory الأقفال والتراجع الذري تحت التزامن. الاختباران جاهزان للبيئة التي تشغل LocalDB، ولا تدعي هذه النتيجة التحقق على قاعدة الإنتاج.

نجح بناء Api وWorker وBootstrap. من اختبارات Domain الحالية نجحت 273 وفشل اختبار قائمة نقاط الدخول العامة بسبب `ImportFuelCards` خارج تغيير جاهز. اختبارات Fleet الحالية لديها أخطاء بناء سابقة في مراجع منشئ `FleetService`؛ لم تُعدل هذه الملفات ضمن تنفيذ جاهز.
